# 系统优化说明（对标同类系统，只优化不删功能）

> 目标：参考 GitHub / Gitee 上同类「安全评估 / 测评管理」系统的做法，对本系统做一轮**精简与优化**。
> **硬性约束：原有功能不做减法**——所有既有能力（登录与权限、项目 CRUD、477 项三级评估、评分、图表、
> 风险源分析、Word 调研表导入、准则 Excel 导入、Excel/报告导出、JSON 备份、用户管理页）全部保留。

---

## 1. 同类系统调研结论

| 参考对象 | 类型 | 值得借鉴的做法 |
|---|---|---|
| [DHWxiao/EvaluationTools](https://github.com/DHWxiao/EvaluationTools)（网络安全等级保护测评辅助系统） | 现场测评工具（Go+SQLite，免安装单文件） | ①「默认作业指导书 + 用户自定义覆盖 + 删除即还原默认」的模板机制；②内置「结果记录/问题描述/整改建议」模板；③指标与高风险判定联动，逐项不漏；④单文件分发、秒开 |
| [信通院「中小企业数据安全工具箱」](https://www.isc.org.cn/mobile/article/21433325949546496.html) | 轻量自评（5 维度 20 项） | 简洁设问 + 总体赋分 + 指标分析 + 能力雷达图，强调「便捷易用」 |
| [intsigSecurity/DPiSR-evaluation-skill](https://github.com/intsigSecurity/DPiSR-evaluation-skill) | 标准自动评价 | 依标准评价 → 自评价结果 + 改进建议（本系统已有「改进建议」生成） |
| [JDArmy/DSRE](https://github.com/JDArmy/DSRE) | 风险枚举框架 | 清单化、枚举式组织风险 |
| [ccampo133/dmap](https://github.com/ccampo133/dmap) | 开源数据安全态势评估 | 规则/配置驱动，纯本地运行 |
| 行业评估表模板（政务、金融等招标/标准文件） | 表格模板 | 「一级/二级/三级 + 权重值 + 评估结果 + 备注」的表格化呈现 |

**共性结论**：同类系统普遍强调「**秒开、免安装、模块化分区、模板与判定口径统一**」，
而平台型厂商产品（资产发现、扫描器、分类分级引擎）不属于本系统的定位，不做对标。

据此，本系统的优化方向定为四类：**首屏性能、统计口径唯一化、交互效率、维护成本**。

## 2. 优化清单（前后对比）

### 2.1 首屏性能：重型库按需加载

| 项目 | 优化前 | 优化后 |
|---|---|---|
| 首屏同步加载 | `index.html` 头部同步引入 ECharts(1,024,740B) + SheetJS(425,020B) + Mammoth(642,759B) | 三者移出首屏，改用 `js/libs.js` 的 `loadLib()` 按需拉取 |
| 首屏体积 | ≈ **2,216,210 B** | ≈ **123,691 B**（**-94%**） |
| 触发时机 | 一律启动即加载 | Excel 导出/导入时才加载 SheetJS；图表渲染时加载 ECharts；Word 导入时加载 Mammoth |
| 用户管理页 | 无端引入 1.4MB 从未使用的库 | 已移除 |

实现：`js/libs.js` 暴露 `loadLib(name)`（Promise 化 + 并发去重 + 失败回退）与 `preloadLib(name)`（空闲预取）；
`charts.js` / `excel.js` / `criteria-import.js` / `word-import.js` 在调用前 `await loadLib(...)`。

### 2.2 判定与统计口径唯一化

优化前：判定结果字符串的比较散落在 `project.js` / `charts.js` / `excel.js` / `dashboard.js` 共 **35 处**，
配色与徽章样式各写一份，容易出现「改了这里漏了那里」的口径漂移。

优化后：新增 `js/stats.js` 作为唯一数据源：

- `RESULT`（符合/部分符合/不符合/不适用）、`RESULT_META`（徽章样式 + 配色 + 下拉标签）、`RESULT_OPTIONS`
- `getResultStatusClass()` / `getResultColor()` / `isAssessed()` / `isScored()` / `scoreFormula()`
- `computeItemStats(project)`：整体统计（总数/符合/部分符合/不符合/不适用/未评估/已评估/计分项/得分）
- `computeL1Stats(project)`：各维度统计（含 `scored = total - na`，供评分与雷达图共用）

**行为一致性已用测试证明**：`scripts/test_stats.node.js` 把重构前的原始实现作为参照物，
对「随机分布 / 全部不适用 / 全部未评估 / 仅前 100 项已评估 / 空项目」5 种场景逐项比对，
整体与各维度统计（含 `Math.round` 取整、分母口径）**完全一致**。

### 2.3 统计结果缓存

`computeItemStats()` / `computeL1Stats()` 以「项目ID + 数据版本号」为键缓存；
`storage.js` 在每次 `saveProject/saveProjects` 时递增版本号，数据一变缓存自动失效。

效果：保存一个指标后原本会连续三次全量遍历 477 项（统计卡 + 图表 + 评分），现在只遍历一次，其余命中缓存。

### 2.4 保存与渲染优化

| 项 | 优化前 | 优化后 |
|---|---|---|
| 指标保存 | 无论是否修改都落盘 + 重绘统计/图表/评分 | 内容未变更直接返回（切换指标、点击空白处等高频场景不再落盘/重绘） |
| 树搜索 | 每输入一个字符全量重绘 477 项 | `scheduleRenderTree()` 220ms 防抖 |
| 图表渲染 | 每次重绘都 `dispose()` + `init()`，且会丢失当前图表类型（雷达图编辑后被重置为柱状图） | 复用实例、仅切换类型时重建；新增 `currentChartType` 保持用户所选类型（同时修掉上述小缺陷） |
| 批量操作 | `batchSetByL1/L2/L3` 三份几乎相同的逻辑 | 合并为 `batchSetByResult(matchFn, result)`，并跳过无变化的批量设置 |
| 评审卡/图表/评分调用 | 6 处重复的 `renderProjectStats + renderChart + generateFinalScore` 三连 | 统一为 `refreshProjectViews(project)` |
| 仪表盘统计 | 无用的全量遍历（`totalItems/completedItems` 计算后未使用） | 移除；完成度改用 `computeItemStats` |

### 2.5 交互效率（新增能力，原有功能不动）

- **项目页区块导航**：`📋 项目信息 / 🏆 评分结果 / ⚠️ 风险源 / 📈 图表 / 📝 指标填写` 粘性导航条，
  滚动时自动高亮当前区块，长页面一键直达。
- **指标弹窗快捷键**：`1/2/3/4` 快速判定（符合/部分符合/不符合/不适用）、`Ctrl+S` 保存并关闭、
  `Alt+↑/↓` 跳到上/下一条**未评估**指标、`Ctrl+←/→` 上下翻项、`ESC` 关闭；弹窗底部有提示。
- 输入框内不拦截数字键，不影响正常录入。

### 2.6 维护成本

- **模板数据单一来源**：此前 `js/template.js` 与 `data/template_data.json` 两份需人工保持一致。
  现以 `data/template_data.json` 为唯一数据源，`scripts/sync_template.py` 生成 `js/template.js`，
  并支持 `--check` 校验；`import_criteria.py --emit-json` 更新数据源后会自动同步生成 JS。
- **自检脚本**：新增 `check_wiring.node.js`（HTML 事件处理函数是否都有定义）、`test_stats.node.js`（统计口径回归）。

## 3. 验证结果

```bash
python scripts/sync_template.py --check      # ✓ js/template.js 与数据源一致（477 项）
node scripts/check_wiring.node.js            # ✓ 事件接线检查通过（155 个函数，0 处未定义）
node scripts/test_stats.node.js              # ✓ ALL PASS（5 场景 + 缓存 + 判定元数据）
node scripts/test_criteria_import.node.js    # ✓ DONE（477 项解析与映射，无 FAIL）
```

- 全部 JS 文件 `node --check` 语法通过；
- 本地服务实测：`index.html` 引用的 20 个资源全部 200（JS 为 `text/javascript; charset=utf-8`），
  懒加载的三个库也能正常按需返回；
- 首屏同步体积由 2,216,210 B 降至 123,691 B（**-94%**）。

## 4. 本次未纳入的候选优化（可后续按需再做）

以下为调研中发现、但会改变现有形态或属于「加功能」的项，本次**未实施**，列出供决策：

1. **录入模板库 / 短语库**（借鉴 EvaluationTools 的「结果记录、问题描述、整改建议」模板）：
   一键插入常用记录句式与整改建议，可进一步提速，但属于新增功能。
2. **权重与赋分**（借鉴行业评估表的「权重值 L + 评估结果 R」）：支持按维度/指标设权重并加权计分，
   当前等权公式需保留为默认口径。
3. **项目状态与任务管理**（进行中/已完成/关闭、责任人、截止时间）：现有「完成度 ≥90% 视为已完成」的轻量口径可继续沿用。
4. **内联样式收敛**：`index.html` 仍有 69 处内联 `style=`，可抽为公共 CSS 类，属纯美化改动、回归风险高，故未动。
5. **风险源分析与准则指标的自动联动**：可按「不符合」项自动生成风险源建议，属于新增能力。
