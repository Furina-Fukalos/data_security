# 评估报告与整改建议设计说明

> 需求：让「导出报告」不只是罗列分数，而是依据**实际测评指标内容**，给出
> **测评结论**与**不符合项、部分符合项的整改建议**，且建议需有**规范依据**支撑。
>
> 实现：`js/report.js`（规范依据库 + 整改规则库 + 结论判定 + Markdown/HTML 渲染）
> 验证：`scripts/test_report.node.js`　示例：`docs/示例报告_数据安全评估.html`

---

## 1. 报告结构

| 章节 | 内容 |
|---|---|
| 一、项目基本信息 | 项目名称、评估对象、评估人员、评估日期、适用对象范围、评估准则来源 |
| 二、测评结论 | 综合结论（符合/基本符合/部分符合/不符合）、综合得分、总体风险等级、结论文本；**判定依据**（逐条列出）；**各维度结论**（得分 + 结论 + 四类计数） |
| 三、评估概况 | 指标总数 / 符合 / 部分符合 / 不符合 / 不适用 / 未评估 / 已评估 / 参评项 + 评分公式；未评估项提示 |
| 四、整改建议汇总 | 需整改总数、P1/P2/P3 数量与时限、按维度的整改分布 |
| 五、P1 立即整改项 | 逐项：维度路径、判定结果、评估指引原文、适用对象、取证位置、评估记录、问题描述、整改措施、规范依据、建议时限 |
| 六、P2 限期整改项 | 同上 |
| 七、P3 持续改进项 | 部分符合项，同上（措辞为"已部分落实，仍存在欠缺"） |
| 八、系统性整改建议 | 整改闭环、制度与技术并重、重要数据专项、未评估项补齐、年度长效机制 |
| 附 | 主要规范依据清单 + 免责说明 |

导出格式：
- **HTML**（推荐）：自带打印样式，浏览器打开后可"打印 → 另存为 PDF"，适合作为提交件；
- **Markdown**：便于二次编辑与归档；
- 原有**简版文本报告**保留（`exportScoreReport()`）。

## 2. 测评结论判定口径

### 2.1 等级与风险等级

以综合得分 `S = 100×(X+0.5Y)/(X+Y+Z)`（X=符合、Y=部分符合、Z=不符合，**不适用不计入**）
结合**不符合项数量**判定：

| 条件 | 综合结论 | 初始风险等级 |
|---|---|---|
| S ≥ 90 且 无不符合项 | 符合 | 低风险 |
| S ≥ 80 且 无不符合项 | 基本符合 | 低风险 |
| S ≥ 80 且 存在不符合项 | 基本符合 | 中低风险 |
| 70 ≤ S < 80 | 部分符合 | 中风险 |
| 60 ≤ S < 70 | 部分符合 | 较高风险 |
| S < 60 | 不符合 | 高风险 |

**风险等级上浮规则**：若存在**涉及重要数据/核心数据**的不符合项，风险等级自动上浮一档
（依据《数据安全法》第二十一条分类分级保护、《网络数据安全管理条例》第二十九条重要数据保护的从严要求）。

### 2.2 判定依据（报告自动输出）

1. 综合得分与公式、各判定计数、不适用项数量；
2. 指标总数与四类计数、未评估数；
3. 不符合项数量提示；
4. 涉及重要数据的不符合项数量（如触发上浮，明确写出）；
5. 未评估项提示（影响结论完整性）；
6. 短板维度（得分 < 80 的维度）列表。

> 各维度结论单独判定：≥90 符合、≥80 基本符合、≥70 部分符合、≥60 部分符合（偏低）、<60 不符合。

## 3. 整改建议规则库

### 3.1 匹配策略

每条指标（`l1/l2/l3 + 评估指引 + 适用对象`）与规则库匹配：

1. 规则需满足维度条件（`dim` 等于该指标所属维度，或为 `*` 通用规则）；
2. 规则的任一关键词命中指标文本即算命中；
3. 命中多条时，**按关键词长度（具体度）降序**，最具体的一条作为"问题描述"，其余规则的措施与依据**合并去重**（措施最多 6 条）；
4. 无关键词命中时，回落到该维度的**基线规则**；再兜底通用基线规则。

规则库当前 **70+ 条**，覆盖：数据安全管理（制度/组织/分类分级/人员/合作外包/应急/开发运维/安全评估/云数据安全）、
数据处理活动（收集/存储/存储介质/使用/传输/监测/提供共享/公开/删除销毁/出境/合并分立）、
数据安全技术（网络/身份认证/加密/脱敏/审计/备份/DLP/接口/监测）、个人信息保护（合法性/告知同意/敏感信息/未成年人/权利响应/自动化决策/影响评估/规模阈值）等。

### 3.2 优先级规则

| 优先级 | 判定条件 | 建议时限 |
|---|---|---|
| **P1 立即整改** | 判定为"不符合"，且命中 P1 规则、或命中法定关键义务规则（应急预案、数据出境、敏感个人信息、未成年人、重要数据目录、风险评估与报送、对外提供、销毁）、或指标涉及重要数据/核心数据、或指引含"重要数据/核心数据/出境/跨境/单独同意/未成年人" | 1 个月内 |
| **P2 限期整改** | 其他"不符合"项 | 3 个月内 |
| **P3 持续改进** | 全部"部分符合"项 | 6 个月内 |

### 3.3 措辞区分

- 不符合项：直接输出问题描述（如"政务数据委托处理的批准程序与受托方监督不到位。"）；
- 部分符合项：统一改为"该项要求已部分落实，仍存在欠缺：……"，避免与"完全未落实"混淆。

## 4. 规范依据来源

| 类型 | 依据 |
|---|---|
| 法律 | 《数据安全法》《个人信息保护法》《网络安全法》 |
| 行政法规 | 《网络数据安全管理条例》（国务院令第790号，**2025-01-01 施行**，全文核对后按条引用） |
| 国家标准 | GB/T 43697-2024《数据安全技术 数据安全风险评估方法》、GB/T 41479-2022《信息安全技术 网络数据处理安全要求》、GB/T 35273-2020《信息安全技术 个人信息安全规范》、GB/T 37988-2019《信息安全技术 数据安全能力成熟度模型》、GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》、GB/T 39335-2020《信息安全技术 个人信息安全影响评估指南》 |
| 部门规章 | 《工业和信息化领域数据安全管理办法（试行）》 |

引用颗粒度：
- 《网络数据安全管理条例》条款为**逐条核对**后引用（第九、十、十一、十二、十四、十五、十六、二十、二十一~二十四、二十七~三十三、三十五、三十七、四十二条等）；
- 《数据安全法》《个人信息保护法》《网络安全法》引用**常用且明确**的条款（如数据安全法第二十一条、二十七条、二十九条、三十条；个保法第六、十三、十七、二十一、二十四、二十五、二十九、三十一、四十四、四十七、五十一、五十二、五十五、五十六条）；
- 条款号不确定的场景**只引用法律名称**，不臆造条款号；
- 报告末尾附免责说明：条款引用供整改参考，具体适用以现行有效文本及主管部门要求为准。

## 5. 使用方式

1. 打开项目 → 「🏆 评估评分结果」卡片 → 点击 **📋 导出报告**；
2. 弹窗中显示结论摘要（结论/得分/风险等级/整改项统计）与**完整报告在线预览**；
3. 选择导出：`📄 完整报告（HTML•可打印/转PDF）`、`📝 完整报告（Markdown）`、或 `📋 简版报告（原有文本格式）`。

## 6. 验证结果

`node scripts/test_report.node.js`（4 个场景、26 项断言全部通过）：

| 场景 | 验证点 |
|---|---|
| 导入准则 Excel 的真实数据 | 7 项不符合 + 263 项部分符合 = **270 项整改清单全覆盖**；P1 7 / P3 263；结论"不符合 / 高风险（56 分）"；专项规则命中率 **91.1%**；依据键 100% 可解析；Markdown/HTML 标签配对且无 `undefined` 泄漏 |
| 全部符合 | 结论"符合 / 低风险"、无整改项、不输出空章节 |
| 全部不符合 | 结论"不符合 / 高风险"、477 项全部进入清单、P1/P2 分级正常、识别 36 项涉及重要数据并上浮风险 |
| 无评估记录 | 无整改项、提示未评估、仍能正常出报告 |
