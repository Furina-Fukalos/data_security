# 评估报告导入设计说明（PDF）

> 需求：新增「报告导入」功能——导入《数据安全风险评估报告》PDF 后，识别报告内的
> **单位名称、系统信息、测评指标情况**（评估项 / 评估记录 / 判定结果），导入系统以便继续修改。
> 约束：**只导入系统已有的字段**；系统没有对应字段的信息（风险源描述、风险等级、整改建议等）不导入。
>
> 实现：`js/report-import.js`　验证：`scripts/test_report_import.node.js`

---

## 1. 关键发现：报告与系统不是同一套指标体系

对样例报告《数据安全风险评估报告v1.6.pdf》（112 页，数字重庆OA系统）分析：

| | 报告 | 系统内置模板 |
|---|---|---|
| 结构 | 一级指标 / 二级指标 / **评估项** / 评估记录 / 评估结果 / 风险源描述 | 一级 / 二级 / **三级指标** + 评估指引 |
| 数量 | **101 项** | 477 项 |
| 二级指标举例 | 组织保障、制度体系、委托管理、数据存储、数据销毁… | 2.安全组织机构、1.安全管理制度、5.合作外包管理、2.数据存储、7.数据删除… |
| 评估项举例 | "应建立数据处理安全组织，包含决策层、管理层、执行层、协作层和监督层" | "1）数据安全管理机构和职能设置情况。" |

实测（IDF 加权 n-gram 包含度 + 二级指标分组）自动匹配率仅 **65/99 ≈ 66%**，且几乎全部为低置信度近似匹配，
其余报告项无对应指标可挂 —— 强行映射会造成**数据错位 + 34% 数据丢失**。

**因此采用「报告测评项作为该项目专属准则」方案**（用户确认）：
101 项报告测评项原样进入项目，评估记录与判定结果 1:1 保真；系统内置 477 项准则与其他项目**不受影响**。

## 2. 字段映射（只导入系统已有字段）

| 报告中的信息 | 系统字段 | 说明 |
|---|---|---|
| 被评估单位 / 单位名称 | `project.target`（评估对象） | 必填，可在导入前修改 |
| 系统名称（如"数字重庆OA系统"） | `project.name`（项目名称） | 默认拼为"XX系统数据安全风险评估"，可改 |
| 报告日期（取正文最大日期） | `project.date` | 如 2025-11-25 |
| 被评估对象描述（1.4 节） | `project.desc` + `wordSurveyData.systemDesc` | 项目描述/系统功能描述 |
| 统一社会信用代码 | `wordSurveyData.basicInfo['统一社会信用代码']` | 系统已有该字段（Word 调研表同款） |
| 测评项（评估项） | 项目专属准则的 `guidance`（+`l1`/`l2` 层级） | 每项独立，不再做强行匹配 |
| 评估记录 | `project.items[i].record` | 原样导入 |
| 判定结果 | `project.items[i].result` | 基本符合→部分符合；含不适用 |
| 报告编号、委托单位、检验机构、联系方式、单位地址… | **不导入** | 系统无对应字段 |
| 风险源描述、风险等级、整改建议、渗透测试/漏洞扫描详情 | **不导入** | 系统无对应字段（按需求要求） |

## 3. PDF 解析技术方案

浏览器端用 **pdf.js 3.11.174**（`vendor/pdf.min.js` + `worker`，按需加载，不影响首屏）。

### 3.1 表格定位与切分（关键）

该报告的测评表是**多行多列、单元格文本大量换行、一级/二级指标竖排**的复杂表格，
单纯按文本行无法正确切分（实测：竖排标签会跨行错位、单元格顶对齐导致锚点失效）。

解决方案：**利用表格的矢量边框线精确切分单元格**：

1. 从 `page.getOperatorList()` 解析路径绘制指令（`constructPath` / `transform` / `stroke` / `fill`），
   按绘制时的 CTM 变换到页面坐标，得到全部横线与竖线（含长度/跨度）；
2. **列边界**：取长度 200–5000pt 的竖线（排除页面边框与短装饰线），按 x 聚类（容差 1.5pt），
   保留在 ≥50% 表格页出现的 8 条 → 恰好是 7 列的列边界；
3. **行带**：取跨表宽 ≥70% 的横线，按 y 聚类 → 行分隔线，相邻两条之间为一个行带；
4. **单元格**：按文本中心点落到（列区间 × 行带）完成归类，同格文本按 y/x 排序拼接；
5. **记录切分**：`序号` 列为纯数字 → 新记录；否则视为跨页续行并入当前记录；
6. **停止条件**：遇到章节标题（字号 ≥14.5pt，如"附录B 技术测试详情"）即停止该页后续行带解析。

> 该方案在样例报告上与 PyMuPDF 结果**逐值一致**（8 条列边界、行分隔线完全吻合）。

### 3.2 单位/系统信息提取

- 封面为竖排标签（"系统名称"四字竖排）+ 横排取值，pdf.js 会把它们合并为同一行（如"系统名称数字重庆OA系统"），
  按标签前缀取值即可；
- 基本信息表按 `单位名称 / 统一社会信用代码 / ...` 标签取同行右侧文本（含换行续接）；
- 报告日期取正文前 25 页中出现的最大日期。

### 3.3 版面解析容错

- 矢量线提取失败时降级为纯文本解析（不中断导入）；
- 章节标题、页眉页脚（`标识号：`、`第X页/共Y页`）、`附录`/`表A-` 前缀文本在归格时被过滤；
- 解析结果先进**预览**（识别到的元信息 + 测评项统计 + 前 8 条明细），用户确认/修改后才落库。

## 4. 项目专属准则（架构增强）

为支持"报告框架 ≠ 内置框架"，新增项目级准则能力（纯增强，不改变原有行为）：

```js
// storage.js
getProjectCriteria(project)  // 项目带 criteria 用项目的，否则返回内置 TEMPLATE
hasCustomCriteria(project)
```

- 项目结构新增可选字段 `criteria`（指标清单）与 `criteriaSource`（来源）；
- `computeL1Stats` / 树形渲染 / 评分 / 图表 / Excel 导出 / 报告生成等**所有项目相关逻辑**改用 `getProjectCriteria(project)`；
- **未携带 criteria 的既有项目行为完全不变**（仍用内置 477 项）；
- 导入报告生成的项目：`criteria` = 101 项报告测评项（`l1`=报告一级指标，`l2`=报告二级指标，
  `l3`='评估项'，`guidance`=评估项全文）；项目信息中显示"评估准则：项目专属准则（101 项，来源：xxx.pdf）"。

## 6. 使用方式

1. 仪表盘点击 **📄 导入报告**（评估组长/管理员）；
2. 选择 PDF 报告 → 自动解析（首次会加载 PDF 组件）→ 预览识别结果；
3. 核对/修改项目名称、评估对象、评估人员、评估日期、项目描述；
4. 点击 **✅ 确认导入** → 自动创建并打开项目，可逐项继续修改。

## 7. 验证与限制

**回归测试** `node scripts/test_report_import.node.js`（端到端，使用真实 PDF）：

- 页数/记录数/序号连续性；评估项、评估记录、判定结果完整率；
- 维度分布与判定分布；元信息（单位/系统/信用代码/报告编号/日期）；
- 项目构建：专属准则 101 项、记录 101 条、统计口径为 101（非 477）、内置模板未受影响；
- 反向校验：`风险源描述` 等系统没有的字段未进入项目；
- 集成校验：由导入的项目可直接生成 Markdown/HTML 整改报告（结论"部分符合/较高风险"，30 项整改清单）。

**已知限制**：

1. 仅支持 **PDF**（用户确认范围）；报告须为**文字型 PDF**（扫描件需先 OCR）；
2. 表格识别依赖**矢量边框线**；若某报告表格用底色而非边框绘制，列边界识别会退化
   （预览仍可用，但可能解析不全）；
3. 竖排的"一级/二级指标"若恰好跨页截断，可能出现标签拼接（预览中可人工核对）；
4. 报告若要匹配到系统内置 477 项框架，需另行处理（本次按"项目专属准则"方案，保真优先）。
